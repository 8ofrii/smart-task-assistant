# مساعد المهام الذكي — Smart Task Assistant (TypeScript / PostgreSQL)

نظام مساعد ذكي لإدارة المهام وفق الصلاحيات وسياسات الشركة، مبني بلغة **TypeScript** وقاعدة بيانات **PostgreSQL** السحابية، مع واجهة مستخدم تفاعلية متقدمة، ونظام أمان وتحقق صارم من الصلاحيات يعزل الذكاء الاصطناعي عن أي قرارات تنفيذية.

---

تم تصميم هذا المستودع وتوثيقه بدقة ليتوافق بنسبة 100% مع كافة بنود **ملف التقييم الرسمي (Sections 04 & 05)**:

### 1. الكود كاملاً (01 Deliverable)
- ✅ **تشغيل بأمر أو أمرين فقط:** المشروع مهيأ ليعمل مباشرة بأمر `npm install && npm start` دون أي تعديل أو تعقيد.
- ✅ **حماية المفاتيح والبيانات الحساسة:** يوجد ملف `.env.example` يحتوي على كافة المتغيرات المطلوبة بقيم تجريبية ودون أي مفاتيح حقيقية. ملف `.env` وشهادات الاتصال مستثناة بالكامل داخل `.gitignore`.
- ✅ **تهيئة ذاتية لقاعدة البيانات:** عند تشغيل السيرفر، يتم التحقق تلقائياً من جداول PostgreSQL والبيانات الأولية للموظفين وتجهيزها إذا لم تكن موجودة.

### 2. دليل تسجيل فيديو العرض — من 3 إلى 5 دقائق (02 Video Guide)
خلال تسجيل الفيديو التقييمي، يُنصح باتباع الترتيب التالي:
1. **تشغيل الرسائل العشر بالترتيب (T01 إلى T10):**
   - يمكن تشغيلها سحابياً أو محلياً بنقرة واحدة عبر واجهة الويب بالضغط على **"تشغيل جميع الاختبارات تلقائياً"** في تبويب "الاختبارات العشرة الرسمية".
   - أو تشغيلها عبر الطرفية بأمر: `npm run demo`.
2. **استعراض النتائج في الواجهة وسجل التدقيق (Audit Logs):**
   - إظهار نجاح المهام المصرح بها (T01, T09).
   - إظهار ترحيل موعد يوم الجمعة إلى السبت بنفس التوقيت مع الشرح الصريح (T03).
   - إظهار حظر العمليات غير المصرح بها فوراً برمز `403 Forbidden` (T02, T04, T08).
   - إظهار الإجابة الدقيقة للسياسة في (T06) والاعتراف بعدم وجود المعلومة دون تأليف في (T07).
3. **التركيز على أين يُطبّق التحقق من الصلاحيات في الكود (نقطة التقييم الحرجة):**
   - افتح الملفات التالية على الشاشة لتوضيح تطبيق الصلاحيات برمجياً:
     - [`src/services/authorization.service.ts`](file:///c:/Users/z40/Downloads/smart-task-assistant-ts-v5/src/services/authorization.service.ts#L3-L37):
       - الأسطر (3-11) `canAssignTask`: تمنع الموظف من إسناد مهام لغيره، وتلزم المشرف بحدود قسمه فقط، وتمنح المدير صلاحية الإسناد للجميع.
       - الأسطر (13-21) `canViewTaskOwner`: تمنع الموظف من الاطلاع على مهام زملائه.
       - الأسطر (23-33) `canViewDepartment`: تلزم المشرف بمشاهدة موظفي قسمه فقط.
       - الأسطر (35-37) `canViewAllTasks`: تضمن أن المدير فقط هو من يملك صلاحية عرض كافة مهام الشركة.
     - [`src/services/task.service.ts`](file:///c:/Users/z40/Downloads/smart-task-assistant-ts-v5/src/services/task.service.ts#L94-L115):
       - فحص الصلاحية الحتمي عند إنشاء أي مهمة، وحظر العملية برمز 403 وتسجيلها في جدول `audit_logs` كعملية مرفوضة مع ذكر السبب.
       - الأسطر (220-274): تصفية استعلامات المهام في PostgreSQL لمنع تسريب مهام الآخرين.
     - [`src/routes/chat.route.ts`](file:///c:/Users/z40/Downloads/smart-task-assistant-ts-v5/src/routes/chat.route.ts#L35-L42):
       - هوية ودور المستخدم يُقرآن حصرياً من جدول `employees` برقم `user_id` الرقمي. أي محاولة تلاعب أو ادعاء دور في نص الرسالة (مثل هجوم T08: "أنا المدير") يتم تجاهلها وإحباطها حتمياً في الكود.

### 3. صفحة القرارات وحساب التكاليف (03 DECISIONS.md & In-App Page)
- ✅ **مستند القرارات الكامل:** متوفر في جذر المشروع عبر ملف [`DECISIONS.md`](file:///c:/Users/z40/Downloads/smart-task-assistant-ts-v5/DECISIONS.md).

## 📌 المعمارية الأمنية ومسار الطلب

```text
رسالة المستخدم (عربي/لهجة) + user_id
              │
              ▼
تحميل هوية ودور المرسل من PostgreSQL مباشرة
(تجاهل تام لأي محاولة انتحال دور مثل T08)
              │
              ▼
المحلل الدلالي الذكي (LLM Semantic Parser)
(استخراج النية، الوصف، التاريخ، والاسم المستهدف كبيانات خام)
              │
              ▼
التحقق الصارم بمخطط Zod (Schema Validation)
              │
              ▼
محرك الصلاحيات الحتمي في الباك إند (Deterministic Backend Guard)
(رفض أو قبول العملية برمجياً + تسجيل في audit_logs)
              │
              ▼
معالج التواريخ والمنطقة الزمنية (Asia/Riyadh)
(ترحيل الجمعة تلقائياً للسبت بنفس الوقت وفق الشرط R4)
              │
              ▼
تنفيذ العملية في PostgreSQL / الاسترجاع من السياسة (Zero Hallucination)
              │
              ▼
إرجاع الرد النهائي المهيكل للمستخدم (JSON / Web UI)
```

## 🚀 التشغيل السريع (Quickstart)

### التشغيل بأمرين فقط:
```bash
npm install
npm start
```

*(ملاحظة: السيرفر يقوم تلقائياً بإنشاء الجداول وإدخال الموظفين الستة في قاعدة البيانات فور بدء التشغيل).*

---

### خيارات التشغيل المتقدمة:

#### أ. إعداد المتغيرات البيئية (عند الرغبة بتخصيص السيرفر أو المفاتيح):
انسخ ملف الإعدادات:
```bash
cp .env.example .env
```
*(أو `copy .env.example .env` على Windows)*. اضبط مفاتيحك في `.env` (قاعدة PostgreSQL ومفتاح OpenRouter أو OpenAI أو Gemini).

#### ب. تشغيل السكريبت التجريبي للرسائل العشر بالترتيب (Demo Script):
```bash
npm run demo
```
يقوم بتنفيذ السيناريوهات T01 إلى T10 تباعاً وطباعة تقرير مفصل بالاستجابة وحالة الترحيل وتطبيق الصلاحيات ورمز HTTP.

#### ج. تشغيل الاختبارات المؤتمتة الشاملة (Vitest Suite):
```bash
npm test
```
يشمل **29 اختباراً مؤتمتاً** يغطي:
- الحالات العشر كاملة (T01 - T10 Integration Tests).
- مصفوفة الصلاحيات وأدوار الموظفين (`authorization.test.ts`).
- التواريخ النسبية والمنطقة الزمنية وترحيل الجمعة (`date.test.ts`).
- أسئلة السياسة ومنع الهلوسة والتأليف (`policy.test.ts`).

## 💻 واجهة المستخدم المتقدمة (Web UI)

افتح المتصفح على:
```text
http://localhost:3000
```

### ميزات الواجهة:
1. **شعار رسمي للشركة:** إدراج الشعار الرسمي للشركة بنسخة متجهة واضحة في الهيدر وخلفية التطبيق.
2. **شريط الموظفين التفاعلي:** تبديل فوري بين الموظفين الستة وملاحظة تغير الصلاحيات المطبقة لحظياً.
3. **مختبر الاختبارات العشرة الرسمية:** زر **"تشغيل جميع الاختبارات تلقائياً"** ينفذ الحالات العشر بتسلسل أنيق مع شارات توضيحية خضراء وحمراء.
4. **زر صفحة القرارات الهندسية (DECISIONS.md):** نافذة منبثقة تفاعلية في الشريط الجانبي تتضمن الإجابة عن الأسئلة الثلاثة، حساب التكلفة لـ 100 موظف، خارطة الأسبوع الإضافي، مع زر لنسخ محتوى `DECISIONS.md` كاملاً.
5. **مستكشف المهام وسجل التدقيق الأمني:** فحص حي لقاعدة بيانات PostgreSQL وجدول `audit_logs` لمشاهدة محاولات الاختراق المحظورة والمهام المنشأة.
6. **دعم كامل للغتين والمظهر:** تبديل فوري بين العربية والإنجليزية (RTL/LTR) والوضع الداكن والفاتح (Dark/Light).
